# Pokemon Bank Firmware

Phase 1: Game Boy Link Cable Protocol Implementation

## Overview

This firmware implements the Game Boy Link Cable protocol using the RP2040's PIO
(Programmable I/O) for reliable timing. It acts as a "slave" device that responds
to the Game Boy's clock signal.

## Hardware

- **Board:** Game Boy Zero Link Board with RP2040-Zero
- **MCU:** RP2040 (Dual-core ARM Cortex-M0+ @ 133MHz)

### Pin Mapping

| RP2040 GPIO | Signal | Direction | Description |
|-------------|--------|-----------|-------------|
| GP0 | SC | Input | Serial Clock (from Game Boy) |
| GP1 | SI | Output | Serial In (data TO Game Boy) |
| GP2 | SO | Input | Serial Out (data FROM Game Boy) |
| GP3 | SD | - | Serial Data (directly directly directly for future) |
| GP16 | LED | Output | WS2812 RGB LED (onboard) |

## Building

### Prerequisites

1. **Pico SDK** - Install from https://github.com/raspberrypi/pico-sdk

   ```bash
   # Clone Pico SDK
   git clone https://github.com/raspberrypi/pico-sdk.git
   cd pico-sdk
   git submodule update --init

   # Set environment variable
   export PICO_SDK_PATH=/path/to/pico-sdk
   ```

2. **ARM Toolchain**
   ```bash
   # Arch Linux
   sudo pacman -S arm-none-eabi-gcc arm-none-eabi-newlib

   # Ubuntu/Debian
   sudo apt install gcc-arm-none-eabi libnewlib-arm-none-eabi
   ```

3. **CMake and Make**
   ```bash
   sudo pacman -S cmake make    # Arch
   sudo apt install cmake make  # Ubuntu
   ```

### Build Steps

```bash
cd /path/to/pokemon-bank/firmware

# Create build directory
mkdir build
cd build

# Configure (set PICO_SDK_PATH if not in environment)
cmake .. -DPICO_SDK_PATH=/path/to/pico-sdk

# Build
make -j$(nproc)

# Output: pokemon_bank.uf2
```

## Flashing

### Method 1: BOOTSEL Mode

1. Hold the **BOOT** button on the RP2040-Zero
2. Connect USB cable (or press RESET while holding BOOT)
3. Release BOOT button
4. A USB drive named `RPI-RP2` appears
5. Copy `pokemon_bank.uf2` to the drive
6. Device automatically reboots with new firmware

### Method 2: picotool

```bash
# Install picotool
# ...

# Flash (device must be in BOOTSEL mode or running compatible firmware)
picotool load pokemon_bank.uf2
picotool reboot
```

## Usage

### Serial Console

Connect via USB serial (115200 baud):
- Linux: `/dev/ttyACM0`
- macOS: `/dev/tty.usbmodem*`
- Windows: `COM*`

```bash
# Linux example
picocom -b 115200 /dev/ttyACM0
# or
screen /dev/ttyACM0 115200
```

### Commands

| Key | Command | Description |
|-----|---------|-------------|
| `h` | Help | Show command list |
| `s` | Status | Show connection state and stats |
| `r` | Reset | Reset link interface |
| `t` | Test | Queue test byte (0xAA) |
| `b` | Bootsel | Enter bootloader mode |

### LED Indicators

| Color | State |
|-------|-------|
| Blue (dim) | Idle, waiting for Game Boy |
| Green | Connected to Game Boy |
| Yellow | Data activity |
| Red | Error |

## Testing

### With Real Game Boy

1. Flash the firmware to RP2040-Zero
2. Connect link cable to Game Boy
3. Open serial terminal on PC
4. Start Pokemon Red/Blue/Yellow
5. Go to Pokemon Center upstairs (trade room)
6. Select "Trade Center"
7. Watch serial output for sync bytes!

### Expected Behavior

When the Game Boy enters the trade room, it sends sync bytes (0x00, then other
protocol bytes). You should see:
```
RX: 0x00
RX: 0x00
RX: 0xFE
...
```

## Protocol Notes

The Game Boy Link Cable uses a synchronous serial protocol:

- **Clock:** Generated by master (Game Boy when trading)
- **Speed:** ~8192 Hz typical
- **Format:** 8 bits, MSB first
- **Polarity:** CPOL=1, CPHA=1 (data changes on falling edge, sampled on rising)

Our PIO implementation:
1. Waits for clock to go LOW
2. Outputs next data bit (MSB first)
3. Waits for clock to go HIGH  
4. Samples input bit
5. Repeats 8 times per byte
