# Hardware Specification

## Board: Game Boy Zero Link Board
**Repo:** https://github.com/weimanc/game-boy-zero-link-board

An open-source USB to Game Boy Link Cable adapter using RP2040-Zero.

### Key Features
- Auto-detects voltage via GBVCC (works with DMG 5V, GBC 5V, GBA 3.3V)
- Multiple connector options: GBA edge, GBC edge, IDC port
- Level shifting handled by BOB-12009 (SparkFun bi-directional)

---

## MCU: Waveshare RP2040-Zero

### Specs
- **Chip:** RP2040 (Dual-core ARM Cortex-M0+ @ 133MHz)
- **RAM:** 264KB SRAM
- **Flash:** 2MB onboard
- **USB:** USB-C, USB 1.1 Host/Device
- **GPIO:** 29 total (20 on headers, 9 castellated)
- **PIO:** 8 programmable I/O state machines (critical for GB link timing!)
- **Size:** 23.5mm × 18mm

### Pinout
```
        ┌─────────────────┐
   GP0 ─┤1              20├─ 3V3 (LV power for level shifter)
   GP1 ─┤2              19├─ GND
   GP2 ─┤3              18├─ 3V3
   GP3 ─┤4              17├─ GP29 (ADC3)
   GP4 ─┤5              16├─ GP28 (ADC2)
   GP5 ─┤6              15├─ GP27 (ADC1)
   GND ─┤7              14├─ GP26 (ADC0)
   GP6 ─┤8              13├─ GP15
   GP7 ─┤9              12├─ GP14
   GP8 ─┤10             11├─ GP13
        └────[USB-C]──────┘
        
RGB LED: GP16 (WS2812 on board)
BOOT button: Hold during reset to enter BOOTSEL mode
```

### Flash Programming
1. Hold BOOT button
2. Plug in USB-C (or press RESET while holding BOOT)
3. Appears as mass storage device "RPI-RP2"
4. Drag .uf2 file to it

## Board Pinout (Game Boy Zero Link Board)

### RP2040-Zero → Level Shifter → Game Boy

| RP2040 GPIO | Signal | Level Shifter | Game Boy Pin | Description |
|-------------|--------|---------------|--------------|-------------|
| GP0         | PSC    | LV1 → HV1     | SC (Pin 5)   | Serial Clock |
| GP1         | PSI    | LV2 → HV2     | SI (Pin 3)   | Serial In (TO Game Boy) |
| GP2         | PSO    | LV3 → HV3     | SO (Pin 2)   | Serial Out (FROM Game Boy) |
| GP3         | PSD    | LV4 → HV4     | SD (Pin 4)   | Serial Data |

### Power
- 3.3V from RP2040 → Level Shifter LV side
- GBVCC (from Game Boy, Pin 1) → Level Shifter HV side
- This auto-detects Game Boy voltage (5V for DMG/GBC, 3.3V for GBA)

### Game Boy Link Cable Pinout (looking at cable end)
```
GBC/GBA style:       DMG style:
  ┌─────────┐         ┌─────────┐
  │ 2  4  6 │         │ 1 3 5   │
  │ 1  3  5 │         │  2 4 6  │
  └─────────┘         └─────────┘

Pin 1: VCC (3.3V or 5V)
Pin 2: SO  (Serial Out - data FROM Game Boy)
Pin 3: SI  (Serial In - data TO Game Boy)
Pin 4: SD  (directly directly
Pin 5: SC  (Serial Clock)
Pin 6: GND
```

## Existing Firmware (stacksmashing gb-link-firmware)

From `main.c`:
```c
#define PIN_SCK  0   // Clock (directly directly directly
#define PIN_SIN  1   // Serial In (to RP2040)
#define PIN_SOUT 2   // Serial Out (from RP2040)

// Uses PIO for SPI-like communication
pio_spi_init(spi.pio, spi.sm, cpha1_prog_offs, 8, 4058.838, 1, 1, 
             PIN_SCK, PIN_SOUT, PIN_SIN);
```

The existing firmware:
- Implements basic GB link protocol via PIO
- Exposes USB CDC + WebUSB interface
- Echoes bytes between USB and Game Boy

## Game Boy Link Protocol

### Physical Layer
- **Type:** SPI-like, synchronous serial
- **Clock:** Generated by master (internal clock) OR slave (external clock)
- **Speed:** ~8KHz typical for Pokemon trading
- **Data:** 8 bits per transfer, MSB first

### Pokemon Trading Uses EXTERNAL CLOCK Mode
- Game Boy is master, generates clock on SC line
- Our device is slave, responds on clock edges
- This is critical - we must react to GB's timing, not generate our own

### Timing Requirements
- Must respond within microseconds
- PIO state machines are essential (CPU too slow for bit-banging)
- The existing firmware handles this correctly
